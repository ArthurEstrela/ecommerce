## 1. CONTEXTO DO PROJETO E ARQUITETURA

[cite_start]O sistema é um E-commerce de compras online com fluxo completo de pedido[cite: 72]. [cite_start]O ecossistema é composto por 6 microsserviços (4 obrigatórios e 2 complementares)[cite: 74], além da infraestrutura de apoio.

### Stack Tecnológico Exigido:

- **Backend:** Java 21+, Spring Boot 3+ (Spring Cloud, Spring Data JPA, Spring Web).
- **Frontend:** React com TypeScript, utilizando Axios e Tailwind CSS.
- [cite_start]**Mensageria:** RabbitMQ[cite: 14].
- **RPC:** gRPC (via `grpc-spring-boot-starter`).
- [cite_start]**Service Discovery:** Spring Cloud Netflix Eureka[cite: 19].
- **Banco de Dados:** PostgreSQL (um database lógico por microsserviço).
- **Orquestração:** Docker e Docker Compose.

## 2. ESPECIFICAÇÃO DOS MICROSSERVIÇOS

Implemente detalhadamente os seguintes serviços:

1.  **Service Discovery (Eureka Server):** O coração da rede. [cite_start]Todos os serviços abaixo devem se registrar nele obrigatoriamente[cite: 83].
2.  **Microsserviço de Produto:** Gerencia o catálogo (CRUD completo). Banco de dados próprio.
3.  [cite_start]**Microsserviço de Carrinho:** Gerencia os itens que o usuário deseja comprar[cite: 75].
4.  [cite_start]**Microsserviço de Pedido:** Processa o fechamento da compra[cite: 77].
5.  [cite_start]**Microsserviço de Pagamento:** Simula a transação financeira[cite: 78].
6.  **Microsserviço de Estoque (Proposto 1):** Gerencia a reserva física dos produtos.
7.  **Microsserviço de Notificação (Proposto 2):** Envia alertas simulados para o usuário.

## 3. REQUISITOS TÉCNICOS E INTEGRAÇÕES (CRÍTICOS)

Você DEVE implementar e configurar os seguintes padrões de comunicação:

- [cite_start]**Invocação Remota Síncrona (RPC):** O serviço de **Carrinho** deve se comunicar obrigatoriamente com o serviço de **Pedido** via **gRPC**[cite: 80]. Gere os arquivos `.proto`, os stubs e os canais de comunicação.
- [cite_start]**Comunicação Assíncrona (Filas):** O serviço de **Notificação** deve consumir uma fila dedicada no **RabbitMQ** para processar o envio de mensagens (ex: "Pagamento Aprovado") de forma assíncrona[cite: 14, 15, 82].
- [cite_start]**Publish/Subscribe (Eventos):** Quando um **Pedido** for criado ou um **Pagamento** for aprovado, o sistema deve publicar um evento no RabbitMQ (Exchange do tipo Fanout ou Topic)[cite: 16]. [cite_start]Os serviços de **Estoque** e **Carrinho** (para esvaziar) devem assinar e reagir a esses eventos[cite: 81].
